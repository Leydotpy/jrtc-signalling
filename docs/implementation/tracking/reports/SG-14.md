## Implementation and contract decisions

The gateway's `src/jrtc_signalling/reconnect.py`, `signalling.py`,
`websocket_auth.py` and `media.py` install a worker-local connection-generation
high-water mark before awaiting handoff, fence all unfinished predecessors and
wait for confirmed Janus cleanup. Current authority and moderation are checked
again after waiting. Unknown attachment/detachment retains its conservative fence.
Connection generation, authorization epoch and gateway-owner generation remain
distinct; routing and ownership transfer remain SG-15.

Django's ticket service rechecks the exact session/generation, admission, membership
and permissions under row locks. Resume advances the connection generation without
requesting another approval. `test_gateway_ticket_races.py` covers simultaneous
resumes and permission changes racing resume. State tests cover delayed disconnect
after newer MEDIA_CONNECTED state, and expiry tests preserve durable approval.
No model or migration change was needed.

In synq.js, `packages/client/src/gateway/connection.ts:690` obtains a fresh
resume ticket and opens a new wire. The recovery path at line 933 closes old media,
quietly repairs the authoritative snapshot and rebuilds negotiations. Capture
tracks remain available. Old ACKs, events, refresh continuations and peer operations
cannot alter the replacement. Ambiguous media commands and lost ticket POSTs are
never replayed or guessed. At most six attempts use 0.5/1/2/4/8/8-second backoff
within a 30-second deadline; offline waits and visibility wake checks are bounded.

Only an invalidated lobby grant can reconcile an approval-before-SSE race. The
snapshot must show admission, the same current session/generation and a newer
authorization epoch; the ticket endpoint then checks authority atomically. Waiting,
denied, removed and superseded sessions remain denied. Revoked admitted-media
grants and explicit supersession remain terminal.

`connection.ts:210` completes a meeting-end POST and its final authoritative
snapshot even if that command revokes WS/SSE first. Both requests share the
configured HTTP deadline (15 seconds by default). The snapshot must confirm ended;
a response or pending credential lookup cannot cross into a newer lifetime.
Ordinary HTTP requests retain teardown cancellation. The POST is never replayed.

## Corrections established during verification

1. A pending refresh retained ownership after socket loss and blocked renewal of
   its replacement. Releasing that ownership fixes the deterministic regression;
   old continuations still check wire identity.
2. The isolated fixture loaded Bun's ESM output as a classic script. Its `closed`
   helper collided with native `window.closed`, breaking real close callbacks.
   A local Chrome/WebSocket reproduction failed as a classic script and succeeded
   as a module. `synq/scripts/check_gateway_browser.py` now uses `type="module"`.
3. Real close callbacks exposed lobby approval arriving before SSE. The narrowly
   scoped reconciliation above handles it, with denial, removal, supersession,
   post-snapshot revocation and bounded-retry regressions.
4. A browser run exhausted the original three quick retries at Janus restart.
   Instrumentation showed Janus readiness preceding confirmed cleanup of four
   old handles. Recovery now uses more of its existing 30-second budget. Tests
   cover a backend unavailable beyond the first three attempts and deadline
   cancellation without additional tickets. Cleanup fences were not relaxed.
5. Run 43986217395 restored media after Janus restart, then exposed an end command
   cancelling its own HTTP acknowledgement. Five local regressions reproduced the
   previous behavior; the fix and a sixth credential/lifetime regression pass.
   The browser now deliberately holds the end response until gateway revocation.

Diagnostics retain bounded operation names, counters and timing. They contain
no tickets, identities, raw SDP, ICE addresses or response bodies.
