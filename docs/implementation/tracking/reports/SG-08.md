## Contract and security decisions

Sensitive operations retain SG-04's fresh bounded Django authority preflight.
The validated grant is then applied locally to SDP and the fenced handle. No
gateway ORM, Django SDP relay or Broka negotiation hop was introduced. **A sensitive
transition still incurs an authority HTTP RPC**; this is a deliberate conservative
deviation from a literal zero-Django-hop latency target. Removing that preflight
requires the later trustworthy live revocation/command fence. This task must not
be cited as proof of zero-authority-RPC negotiation or production host revocation.

Every active publisher section must match declared, permitted tracks. SDP does
not attest camera versus screen device provenance. Subscribers can target only
same-meeting publishers owned and ready in this process, with no caller-selected
Janus IDs. Incoming server SDP/layout is also checked; invalid replies after a
mutation become nonretryable `OUTCOME_UNKNOWN` and the handle is disposed.
Janus IDs remain integers internally and decimal strings on the wire; selected
stream nulls are preserved. Room PIN/secret, ticket and full SDP/ICE are not logged
or published as domain observations.

Bounds: 128 media peers, two handles each, 16 global active operations, one ordered
worker per connection, eight queued requests, 16 replies/notifications, separate
256 KiB queue/replay byte caps, 64 replay records, 32 Janus events per peer and
64 publisher negotiation IDs per connection. SDP is at most 64 KiB, with 16
publisher or 256 subscriber media sections. Queue/capacity admission is six
seconds; authority, SDK and send calls have separate existing bounded deadlines.
Timing counters distinguish operation/queue totals and maximum/concurrency; no
production latency percentile or service-level objective is inferred.
