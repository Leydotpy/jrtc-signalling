## Contract and security decisions

`projection_version` is separate from the legacy session version and never
decrements. Every event remains fenced by participant session/generation, current
owner/generation and authorization epoch. Live presence expires at the earlier of
the owner lease and observation occurrence plus 120 seconds; immutable replays do
not refresh that deadline. Ticket refreshes generate fresh observations. Approval
therefore remains independent of connection, and disconnection does not remove a
participant.

Waiting users receive only their own admission/presence and minimal meeting
metadata. Admitted users see eligible admitted peers; authorized waiting-room
moderators additionally see waiting participants. Removed, unrelated and inactive
users are denied. Replay filters against current visibility, never historical
private participant payloads. No token, email, SDP, ICE address, raw Janus ID or
private room topology is exposed in the new public payloads.

SSE sends the existing v1 `state-notification` as a small invalidation, or a quiet
`state.snapshot` on initial connection/gap. Retention is 256 changes per meeting;
snapshots page at 50 other participants and require a consistent version across
pages. The frontend must fetch a snapshot on every accepted invalidation, including
empty participant-ID lists, and ignore versions already superseded by a snapshot.
Browser consumption remains SG-12. Snapshot/replay frames do not command sounds.

Durable one-second polling intentionally replaces an additional Redis Pub/Sub
fanout dependency. Missed delivery, dropped cache writes and subscriber restarts
recover from the database. Each frame is built after its transaction returns;
one transaction barrier test proves an independent observer cannot see an
uncommitted revision. Semantically identical polls/transport refreshes produce no
projection/log writes. Candidate and packet-frequency events never enter this
projector; SG-10 lifecycle inbox/receipt writes remain unchanged.

Streams use existing session/Clerk authentication, cap lifetime at 60 seconds or
verified bearer expiry, recheck local authority per pull, and revalidate Django
sessions per pull. Remote Clerk revocation follows existing authentication/cache
policy and reconnection. There are 32 streams per ASGI worker/four per user per
worker and 128 KiB frames; these are not a deployment-wide quota. Redis is only a
disposable presence cache: its five-minute key TTL retains a high-water fence,
while consumers must enforce each participant's earlier absolute expiry.

## Compatibility and remaining limits

The installed gateway's `state-notification` schema validates the new public
invalidation payloads. Both live cross-repository integrations use the same pinned
gateway/JRTC artifacts. There are no media or ICE wire changes, no new Janus
runtime owner and no claims of a frontend E2E or performance/load qualification.

Rollback is to disable `GATEWAY_STATE_ENABLED`, allow active streams to close on
their next pull, and retain the additive migration/data. Do not undo gateway
ownership fences or route gateway meetings to legacy media as part of rollback.
The state model currently recomputes participants on each poll; large-meeting
query/connection budgets, deployment-wide quotas and proxy timeouts remain
SG-16/17. The optional presence sweep may lag as the cohort grows; public reads
reconcile independently and expired Redis entries cannot authorize activity.

SG-12 frontend adapter/notification consumption is next. SG-12 through SG-18
remain unimplemented. Production cutover remains a separately authorized task.
