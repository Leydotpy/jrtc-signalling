## Implementation evidence

- `src/jrtc_signalling/moderation.py:41`: current-owner enforcement for all five
  command types. Monotonic participant epochs, inclusive denial/disconnect fences,
  immutable meeting termination and bounded deny history. Barriers precede all
  awaited work. Admissions never grant media or manufacture a connection.
- `websocket_auth.py:97` and `signalling.py:239`: post-RPC hello/resume/refresh
  checks, owned socket tracking and cancellation completion. Revocation cancels
  queued and in-flight publishing/ICE and waits for existing shielded cleanup.
  Refresh is serialized with peer authorization to avoid transient grant races.
- `signalling.py:336`: periodic bounded current-authority checks remove idle
  revoked media without broker delivery or cooperative client traffic. Authority
  failure, permission removal and expiry fail closed.
- `janus_runtime.py:262`: confirm detach against the original remote IDs using
  SDK typed requests. Only success or confirmed session/handle absence (458/459)
  counts as cleanup. Known uncertain bindings survive local SDK disposal; unknown
  attachment results retain a meeting-level owner fence.
- `janus_runtime.py:288` and `:307`: bounded fair cleanup retries and participant
  reconciliation. A separate worker performs cleanup so it cannot delay lease
  renewal or the Janus reader. Replacement transports cannot resurrect old tokens.
- `media.py:200`: destroy and confirm absence of the private meeting room;
  retained room credentials enable retry when destruction fails. New participant
  media is refused while its previous handles remain unconfirmed.
- `janus_runtime.py:485`: terminated meetings retain only their existing finite
  lease for cleanup/outcomes; expected renewal refusal does not drain unrelated
  meetings. A regression exercises that boundary through the next renewal cycle.
- Existing signed command inbox/outbox records provide actor/epoch/owner/trace
  audit and stable duplicate receipts. `applied` requires confirmed physical
  enforcement and a final owner check. Timeouts/failures remain honest historical
  outcomes while resource cleanup continues; reconciliation does not rewrite them.
- Physical enforcement uses a burst-20, ten-per-second worker limit. Deny fences
  and socket cancellation are installed before rate limiting. Limits and rollback
  are documented in `docs/MODERATION.md`.
- `tests/test_moderation.py`: 23 adversarial gateway/SDK/wire tests. The new
  `scripts/check_django_moderation.py` runs three actual service integrations;
  `.github/workflows/ci.yml` adds a pinned Synq/PostgreSQL/Redis/Janus CI job.

## Corrections discovered during verification

- The SDK raises structured Janus exceptions for error replies; physical absence
  confirmation now handles 458/459 exceptions as well as typed responses.
- Wire tests distinguish participant media handles from the reusable management
  handle. The latter intentionally remains until runtime shutdown.
- The resumed Synq virtual environment pointed to a removed interpreter. Its
  frozen dependencies were restored in the test environment; no source/lockfile
  changed. Interface enumeration is prohibited in this local runner, so the
  integration uses the established loopback fallback only when that call fails.
- Janus removal correctly closes the remote DTLS peer. The test verifies this
  outcome without calling client `close()` first.
- Django emits participant disconnects after `meeting.terminate`; these can
  confirm already-removed resources, while later admission remains forbidden.
- The Redis-stall integration uses the real supervised Django command worker so
  lost broker subscriptions and publications recover. Merely calling its sweep
  once does not exercise transport recovery.
