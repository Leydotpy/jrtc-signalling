## Measurement boundary

Four simultaneous aiortc audio publishers established WebRTC with a local Janus VideoRoom. Each publisher sent 32 distinct, single-candidate batches on its established negotiation. Every generated candidate addressed a UDP socket bound by the benchmark. The same destination ports were reused across the paired paths. The test verified connected peers and outbound RTP before starting each wave and required an acknowledgement for every batch.

Each row below contains 128 requests. Each participant waited for its reply before sending the next batch. The legacy measurement starts at the real Django Socket.IO namespace callback. The gateway measurement serializes the request and receives the correlated reply through an in-process ASGI WebSocket. Both paths use the real JRTC SDK, Janus and PostgreSQL authority or ownership checks. WAN transit, browser rendering and Socket.IO network framing are outside this comparison. Latencies describe signalling acknowledgements. RTP delay and video quality need separate media-plane measurements.

The script uses nearest-rank percentiles of individual request durations. SQL timing covers all statements executed by the benchmark's Django process during the wave, including concurrent authority or maintenance work. It sums statement execution time across threads. Fresh grant checks use the production cache lifetime and revocation rules.

## Faults and capacity

The gateway completed all four peers' final ICE acknowledgements in 3.71 and 3.37 ms while the private Redis server was paused for 2.5 seconds. A subsequent Redis ping succeeded and all four audio peers were connected. After stopping Janus, the old session became unusable and its live binding table emptied in 369.98 and 411.99 ms. From the start of the fault, full reconciliation took 1.881 and 5.447 seconds. This includes restarting Janus, obtaining a fresh session, clearing uncertain handles and old sockets, and successfully listing rooms.

The multiworker rehearsal admitted a publisher through the standby, routed the WSS session to the elected process, and verified the owner generation in the reply. The direct TLS scrapes recorded the control sessions and handles in each process.

| Worker handling one configured meeting | Owned meetings | Ready Janus sessions | Attached handles |
| --- | ---: | ---: | ---: |
| Elected owner | 1 | 1 | 2 |
| Standby | 0 | 1 | 0 |

One four-publisher gateway worker used one ready Janus session and five attached handles. For an elected pool, budget for one control session per configured meeting on every candidate worker, including the standbys. The session count and handle count scale differently. The two-worker run also exercised rolling SIGTERM, expired ownership and broker recovery across four owner generations.

## Instrumentation and bounds

Gateway counters distinguish accepted and failed admissions, resumes, fixed authorization reasons, relay errors, overloads and moderation reconciliation. Histograms cover successful ICE ACK time, queue wait, event-loop lag and new signed command age. The direct-worker gauges expose actual ready Janus sessions, plugins, uncertain handles, Redis group lag and pending entries. Durable outcome and quarantine gauges can be read during a Redis outage. [Gateway measurements](../../../../src/jrtc_signalling/telemetry.py) · [Dispatch timing](../../../../src/jrtc_signalling/signalling.py) · [Broker sampling](../../../../src/jrtc_signalling/commands.py)

Each control stream caps retention at 4,096 packets of up to 32 KiB. Atomic append permits reclamation only below the oldest pending entry or last delivered entry of the intended reader group. Tests cover competing writes at capacity, an absent or unrelated group, unread work, lost ACKs and subsequent safe recovery. Queue overflow leaves delivery to the existing durable retry mechanism. [Bounded stream transport](../../../../src/jrtc_signalling/bus_transport.py) · [Redis integration tests](../../../../tests/test_command_streams.py)

Django measures live and replay SSE from projection-row creation to frame yield. It reports durable command backlog, oldest outstanding age and retained quarantine entries. Gateway admission and committed Django observations share optional keyed, pseudonymous references with LogVista. The metrics endpoints use independent HTTPS bearer credentials and are disabled by default. The operating guide includes configuration, dashboard queries, signal definitions, suggested alert thresholds, scrape topology and per-process memory and queue limits. [Django telemetry](https://github.com/Leydotpy/synq/blob/90af54cb573826fe46ff508696e0e34fde5b778d/src/apps/meetings/services/gateway_telemetry.py) · [Operating guide](../../../OBSERVABILITY.md)

## Verification and reproduction

Gateway CI passed all seven jobs. Python 3.12, 3.13 and 3.14 each passed 538 tests with eight real-Janus cases selected in a dedicated integration job. That job passed all eight using Janus 1.1.2 and coturn 4.6.1. The authority and moderation integrations, typecheck, lint, format, schema export check, package build and container check also passed. Synq CI passed 254 tests with PostgreSQL 16 and Redis 7.4, migration drift and style checks, live lifecycle and SSE, two-worker failover and both benchmark orders. [Gateway CI](https://github.com/Leydotpy/jrtc-signalling/actions/runs/44463084544) · [Synq CI and benchmark log](https://github.com/Leydotpy/synq/actions/runs/44463194571)

Using the Synq revision above, check out the matching gateway into `gateway-integration`. Use the test database credentials for a disposable PostgreSQL instance. Install Janus, its WebSocket transport and VideoRoom plugin, and a `redis-server` executable. The runner creates a private Redis process on loopback and restarts only its own Janus process.

```sh
export DJANGO_SETTINGS_MODULE=conf.gateway_postgres_test_settings
uv sync --frozen --python 3.14
uv run --frozen --with pytest --with aiortc python scripts/benchmark_gateway_ice.py --gateway gateway-integration --first legacy
uv run --frozen --with pytest --with aiortc python scripts/benchmark_gateway_ice.py --gateway gateway-integration --first gateway
```

`SG16_RESULT` contains one fixed-size JSON summary per order. Participants can be set from 2 to 8 and measured batches from 8 to 48 per peer. The separate `scripts/check_gateway_multiworker.py --gateway gateway-integration` uses the workflow's disposable Redis service and emits `SG16_POOL`. Exact package installation, service settings, lint commands and test invocations are recorded in the two workflows. [Gateway workflow](https://github.com/Leydotpy/jrtc-signalling/blob/2797d26abe6e995e6ad702b0ccb63652bf46f71e/.github/workflows/ci.yml) · [Synq workflow](https://github.com/Leydotpy/synq/blob/90af54cb573826fe46ff508696e0e34fde5b778d/.github/workflows/gateway-control-plane.yml)

The first fault rehearsal detected that a ready replacement transport could appear before uncertain old handles were reconciled. The benchmark now waits for a fresh session, cleared uncertain handles, completed old socket cleanup and a successful management request before declaring recovery. Workloads in this report are short, single-host audio bursts. Sustained production load, internet RTT and meeting sizes above the exercised load remain unmeasured.

Removing the optional metrics and trace key file settings and restarting disables export and trace correlation. Reverting the matched gateway and Synq revisions restores the previous stream behaviour for subsequent writes. Application routing and readiness flags retain their previous values.
