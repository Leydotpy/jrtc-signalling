## Ownership and routing

The gateway reserves an election in Redis and inspects the previous owner through Django. Before activating a successor, it checks that the previous Janus session is unreachable and removes the previous generation's room if it still exists. Each candidate opens a dedicated SDK session for the meeting. The per-generation room credentials allow a successor to reconcile a room whose creation reply was lost. [Election and Janus reconciliation](https://github.com/Leydotpy/jrtc-signalling/blob/1b4ecd125ff730d76ccf1baf2752478572562299/src/jrtc_signalling/multiworker.py#L157)

Django locks the meeting, compares the expected generation and records the elected process, Janus pool and exact session ID. An exact retry after a lost registration reply returns the remaining lease. A retired process, changed pool, live owner or unreleased legacy session cannot acquire the route. A gateway operation checks the current lease and registered SDK session before mutating the meeting. [Django ownership authority](https://github.com/Leydotpy/synq/blob/e0b0481ce05a2b1b18d43ef6f6fad235042009be/src/apps/meetings/services/gateway_ownership.py#L60)

An entry worker validates the signed hello or resume frame before looking up the owner. It may forward the WebSocket over one allowlisted TLS hop. Only the owner consumes the one-use ticket. SDP and ICE travel on the WebSocket and RTP travels directly between client and Janus. Each physical command stream includes the elected process incarnation. The dispatcher preserves command identity across retries and checks the generation again when accepting an outcome. [WebSocket routing](https://github.com/Leydotpy/jrtc-signalling/blob/1b4ecd125ff730d76ccf1baf2752478572562299/src/jrtc_signalling/routing.py#L26) · [Command dispatch](https://github.com/Leydotpy/synq/blob/e0b0481ce05a2b1b18d43ef6f6fad235042009be/src/apps/meetings/services/gateway_commands.py#L93)

On SIGTERM the server withdraws its routes before Uvicorn closes connections. Concurrent shutdown callers wait on the same cleanup. After ownership loss the gateway fences new work, closes sockets and disposes of local Janus resources. A release requires confirmed cleanup. [Gateway shutdown](https://github.com/Leydotpy/jrtc-signalling/blob/1b4ecd125ff730d76ccf1baf2752478572562299/src/jrtc_signalling/__main__.py#L15)

## Operating limits and rollback

Each advertised worker needs a distinct direct TLS endpoint. The pool must address one direct Janus instance. Each candidate opens one Janus control session per configured meeting, including on standby, up to the existing 16-meeting configuration limit. A process that loses ownership fences its local meetings and needs a fresh incarnation to rejoin. A change of Janus URL or secret requires reconciling the original pool before takeover.

To roll back, drain the pool, confirm its previous sessions and rooms have closed, disable the pool configuration, and open a new meeting session under the intended backend.
