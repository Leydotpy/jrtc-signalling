## Implementation and authority

Synq `services/gateway_admission.py:89` validates authenticated join intent using
the current Django meeting policy, durable membership, passcode/invite gate and
capacity. Direct entry is a Django decision. Repeated pending requests return
the existing intent. Denied/removed participants cannot mint a fresh ticket or
bypass denial by waiting for the room policy to change.

`services/gateway_admission.py:211` and `api/gateway.py:191` implement host or
delegated moderator decisions from the authenticated server identity. Strict
boolean/epoch input, a principal-bound decision UUID and the expected epoch
prevent spoofed, conflicting or stale decisions. A retry after revocation reports
the current state as superseded and cannot restore permission. Meeting row locks
serialize admission/removal and concurrent retries.

`models.py:850`, `models.py:861` and migration 0015 add decision receipts and a
durable outbox unique per participant/epoch. `services/gateway_outbox.py:17` writes
permission intents in the decision transaction. Existing permission changes,
removal, leave and meeting end also record intents for selected rooms. Outbox
failure rolls back the decision; no publication occurs inside the transaction.

Approval sets ADMITTED, leaving joined_at and media handles unset. It emits no
PARTICIPANT_JOINED observation or Janus task. Responses distinguish admission,
current authorization epoch and pending enforcement. Configuration requires both
GATEWAY_ADMISSION_ENABLED and the room's gateway_control_plane flag; both default
off. The legacy runtime remains available for compatibility.
