## Findings resolved during acceptance

1. **A lobby denial must survive every entry path.** Django now consults the durable rejection on the gateway and compatibility admission paths, ticket authorization and terminal-state reads. The fix also covers pre-existing participant rows inconsistent with an earlier denial. The decision is scoped to the meeting session. [Ticket authority](https://github.com/Leydotpy/synq/blob/0bff1ab929054e56697c2a7a0410d2e76221e555/src/apps/meetings/services/gateway_tickets.py#L90) · [Compatibility admission](https://github.com/Leydotpy/synq/blob/0bff1ab929054e56697c2a7a0410d2e76221e555/src/apps/meetings/services/lifecycle.py#L412) · [State audience](https://github.com/Leydotpy/synq/blob/0bff1ab929054e56697c2a7a0410d2e76221e555/src/apps/meetings/services/gateway_state.py#L62)
2. **Errors exposed private meeting details.** Django's default error log included the session UUID in the URL, LogVista domain messages could contain a room or participant, and PostgreSQL printed rows from intended constraint failures in CI. The Django/Uvicorn filter retains status while clearing the private request and exception context. LogVista receives the exception class. The disposable database reports the constraint without logging row data. Normal Django startup with fixture settings and the real request-log tests passed. A scan of all nine final job logs found zero matches for the reviewed patterns covering signed or bearer tokens, private keys, SDP attributes, ICE candidates, meeting API UUIDs, room-bearing error text and database row dumps. [Request filter](https://github.com/Leydotpy/synq/blob/0bff1ab929054e56697c2a7a0410d2e76221e555/src/conf/logging.py#L9) · [Domain logging](https://github.com/Leydotpy/synq/blob/0bff1ab929054e56697c2a7a0410d2e76221e555/src/apps/meetings/exceptions.py#L15) · [Regression tests](https://github.com/Leydotpy/synq/blob/0bff1ab929054e56697c2a7a0410d2e76221e555/src/apps/meetings/tests/test_gateway_telemetry.py)
3. **An owner needs its remaining time to confirm an ended meeting.** With broker delivery paused, the older opt-in cohort lost its cleanup authority on a heartbeat. Media access closed, but Django could not confirm final cleanup. Both selectors now allow the exact current holder to read the time left on its original lease. The deadline stays fixed. Wrong holders, stale generations, expired leases, fresh ownership claims and new tickets are refused. The live test crossed a real heartbeat before resuming the dispatcher and observing the signed outcome. [Lease guard](https://github.com/Leydotpy/synq/blob/0bff1ab929054e56697c2a7a0410d2e76221e555/src/apps/meetings/services/gateway_ownership.py#L107) · [Deadline regression](https://github.com/Leydotpy/synq/blob/0bff1ab929054e56697c2a7a0410d2e76221e555/src/apps/meetings/tests/test_gateway_ownership.py#L200)
4. **A disconnected request could keep the browser test database open.** A repeat completed all 18 Chromium checks, then PostgreSQL refused to drop the temporary database because one session remained open. The test harness now drains each request and closes its database connections on the thread that opened them. It also waits for its broker workers to stop. The regression holds a real PostgreSQL connection across an early disconnect and checks that the driver has closed it. [Failure after the browser checks](https://github.com/Leydotpy/synq.js/actions/runs/45331479093) · [Request cleanup](https://github.com/Leydotpy/synq/blob/0bff1ab929054e56697c2a7a0410d2e76221e555/scripts/check_gateway_state.py) · [Browser regression](https://github.com/Leydotpy/synq/blob/0bff1ab929054e56697c2a7a0410d2e76221e555/scripts/check_gateway_browser.py) · [Repeat browser run](https://github.com/Leydotpy/synq.js/actions/runs/45333608696)

## Release limits

The browser demo uses genuine Django session cookies for a host and authenticated non-member profiles, a React SDK harness, synthetic microphones and isolated TLS. Hosted Clerk login through the deployed Next.js application, other browser engines, camera/screen sharing across real devices and sustained target-network load require staging evidence. Application and CI log checks cannot establish the configuration of a hosted proxy, identity provider, database or log exporter.

Keep the session's assigned transport through its lifetime. Rehearse failback with a new meeting link after signed termination and confirmed Janus cleanup. An expired lease or an uncertain cleanup outcome keeps recreation blocked. Target-environment sign-off and the separate legacy-retirement review are recorded in the [manual checklist](../../checklists/ACCEPTANCE.md).
