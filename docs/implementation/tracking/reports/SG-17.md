## What changes for a meeting

An operator can select or pause a room for future sessions. Django fixes the transport when a new session starts. Existing sessions keep their assignment. On the staged web app, Django's authenticated route lookup runs before constructing a call. A missing gateway owner or invalid route stops the join. Gateway tickets, Janus access and state permissions are still checked on their existing paths. [Cohort selection](https://github.com/Leydotpy/synq/blob/b36ba62c4500de607ac6d1c836a448d101861365/src/apps/meetings/services/gateway_ownership.py#L22) · [Route lookup](https://github.com/Leydotpy/synq/blob/b36ba62c4500de607ac6d1c836a448d101861365/src/apps/meetings/api/gateway_application.py#L75) · [Web route reader](https://github.com/Leydotpy/synq.js/blob/0affac3f0861105901d0bd73d7c7a282c9f102eb/app/src/lib/gatewayConfig.ts#L10)

Staged ingress opens only when Janus, the broker, the authority and ownership report ready. Draining withdraws ingress. On a worker serving several meetings, an expired lease for a fully drained meeting can coexist with a healthy live meeting. An expired lease with pending cleanup still closes readiness. [Ingress check](https://github.com/Leydotpy/jrtc-signalling/blob/8ad22c05f13a87d04a16189a8ec08bcc0276cec6/src/jrtc_signalling/app.py#L156) · [Lease health](https://github.com/Leydotpy/jrtc-signalling/blob/8ad22c05f13a87d04a16189a8ec08bcc0276cec6/src/jrtc_signalling/janus_runtime.py#L669) · [Multi-meeting regression](https://github.com/Leydotpy/jrtc-signalling/blob/8ad22c05f13a87d04a16189a8ec08bcc0276cec6/tests/test_ownership.py#L140) · [Staged Compose health check](https://github.com/Leydotpy/jrtc-signalling/blob/8ad22c05f13a87d04a16189a8ec08bcc0276cec6/compose.staged.yaml#L15)

## What the rollback proved

| Rehearsal stage | Observed result |
| --- | --- |
| Dark launch and canary | An unselected room published legacy WebRTC audio. A selected room then published gateway audio on the same Janus instance. Both sent RTP. Django refused Janus management for the gateway session and its Celery provisioning and attachment tasks returned `gateway_owned`. |
| Drain with pending work | Django ended the exact gateway session. Before the dispatcher ran, an attempt to start its replacement failed on pending commands. After the signed termination was applied, a second attempt failed while its owner still held the session. |
| Physical release and recreation | An independent legacy Janus session confirmed the old VideoRoom was absent. After clean release, Janus returned error 458 for the exact old session ID. Only then did Django create a distinct legacy session. Both the replacement and the independent legacy call sent RTP. |
| Final state | The old gateway session's snapshot showed an ended meeting and an offline participant. An authenticated SSE request with the pre-drain cursor replayed contiguous versions to that same terminal snapshot. |

The PostgreSQL tests also raced a first owner claim against a drain, checked an unclaimed canary, retried a delayed operator request, and rejected recreation on lease expiry or release without confirmed VideoRoom termination. The browser rehearsal used the same route reader and selector as the staged page. [Recreation guard](https://github.com/Leydotpy/synq/blob/b36ba62c4500de607ac6d1c836a448d101861365/src/apps/meetings/services/gateway_cutover.py#L68) · [Live rehearsal](https://github.com/Leydotpy/synq/blob/b36ba62c4500de607ac6d1c836a448d101861365/scripts/check_gateway_cutover.py#L204) · [Race and failure tests](https://github.com/Leydotpy/synq/blob/b36ba62c4500de607ac6d1c836a448d101861365/src/apps/meetings/tests/test_gateway_cutover.py) · [Chromium probe](https://github.com/Leydotpy/synq.js/blob/0affac3f0861105901d0bd73d7c7a282c9f102eb/packages/client/test/browser/gateway.tsx#L34)

## Operating limits and release decision

Failback deliberately gives the replacement a new meeting link. If the old generation cannot confirm physical cleanup, the room stays blocked. The isolated runner covered a dedicated canary worker and the browser SDK. A hosted Next.js/Clerk deployment, production network conditions and target production concurrency remain outside this evidence. Production cutover and legacy retirement each require a separate maintainer decision.
